# cashforensics

Форензик-анализ операционных касс пунктов выдачи заказов.

На вход — выгрузка из 1С «Карточка счёта 50.2» по одному ПВЗ. В том же листе
справа лежат операционные логи фронтальной системы: блоки РКО (расходные
ордера) и ПКО (приходные ордера). Это два независимых потока данных, строки
которых **не** выровнены между собой.

Приложение отвечает на один главный вопрос: **из-за каких конкретно документов
сальдо кассы на конец периода отличается от целевого** — и раскладывает
отклонение по причинам так, чтобы раскладка сходилась без остатка.

## Что инструмент делает

1. Проверяет полноту и корректность разбора данных (жёсткие контроли V1–V3).
2. Сверяет бухгалтерский учёт с операционными логами по категориям потоков.
3. Отделяет **мнимые** расхождения — тайминг проводок, агрегация выходных,
   служебные операции, срез периода — от реальных.
4. Находит конкретные документы, из-за которых сальдо ушло от целевого.
5. Раскладывает отклонение по причинам без остатка.
6. Выявляет сигнатуры риска, которые сверка принципиально не ловит.
7. Формирует отчёт для службы безопасности и руководства.

## Чего он не делает

**Не квалифицирует находки как хищение или мошенничество.** Умысел не выводится
из данных. Инструмент выдаёт локализованные расхождения и «красные флаги»;
квалификация — за человеком. В отчётах используются слова «расхождение»,
«требует проверки», «сигнатура», но не «фрод», «кража», «виновен».

Не заменяет инвентаризацию кассы и не подтверждает физический остаток. Не
работает ниже дневного агрегата продаж без Z-отчётов.

Не может сказать, **какая из двух систем права** — 1С или опер-лог. Эта развилка
обязана присутствовать в блоке «что проверить» каждого отчёта.

## Три принципа

Нарушение любого считается дефектом, а не стилистическим замечанием.

1. **Детерминированность.** Один и тот же вход при одной версии правил даёт
   побитово идентичный выход. Никаких сортировок без полного явного ключа,
   никакого `random` без seed из конфига.
2. **Объяснимость.** Каждый вывод сопровождается трассировкой: какое правило
   сработало, на каких строках исходного файла, какой остаток и чем погашен.
   Инструмент, который говорит «расхождение 2 579,00», но не может показать
   почему — не выполняет задачу.
3. **Отказ вместо догадки.** При недостаточной доказательной базе возвращается
   статус «не локализовано» с причиной. Правдоподобная, но недоказанная улика —
   худший из возможных исходов: она уйдёт к живому кассиру.

## Конвейер из 12 стадий (§5 ТЗ)

```
ingest → normalize → validate → classify → neutralize_reversals →
reconcile → collapse_timing → balance_trace → localize →
decompose → rank → report
```

Каждая стадия — чистая функция с явными входом и выходом. Стадии не мутируют
вход, промежуточный результат сериализуем.

| # | Стадия | Модуль | § | Назначение |
| --- | --- | --- | --- | --- |
| 1 | `ingest` | `ingest.py` | 5.1 | Чтение `.xlsx`, SHA-256 файла, локация блоков опер-лога **по заголовкам** (позиция плавает — четыре наблюдавшихся варианта), разбор шапки |
| 2 | `normalize` | `normalize.py` | 5.2 | Наследование даты вниз, нормализация `\xa0` и форматов чисел, определение направления проводки (корр. счёт из **G** для дебета, из **E** для кредита) |
| 3 | `validate` | `validate.py` | 5.3 | V1–V3 — жёсткие инварианты, нарушение = остановка. V4–V6 — предупреждения |
| 4 | `classify` | `classify.py` | 5.4 | Категория по корр. счёту; приход = только продажи + авансы. Классификация опер-лога, включая верифицируемый time-fallback |
| 5 | `neutralize_reversals` | `reversals.py` | 5.5 | Гашение сторно-пар + проверка «была ли фактическая выдача»: снятая и не перепроведённая проводка — потеря учёта, а не нейтральная пара |
| 6 | `reconcile` | `reconcile.py` | 5.6 | Нетто, брутто, ratio по трём категориям; возвраты в вариантах «как есть» и «скорректировано» |
| 7 | `collapse_timing` | `timing.py` | 5.7 | Детектор лага + свёртка в три прохода + календарная агрегация выходных. Без неё инструмент показывает сотни ложных строк |
| 8 | `balance_trace` | `balance.py` | 5.8 | Нарастающее сальдо, инвариант неотрицательности, «пол кассы» с фильтром полноты выемки, датирование смещения PELT/CUSUM/EWMA |
| 9 | `localize` | `localize.py` | 5.9 | Сопоставление 1:1, правило единственной проводки, subset-sum **с четырьмя гейтами** §7 |
| 10 | `decompose` | `decompose.py` | 5.10 | Раскладка без остатка и её перевод в причинную форму с документами |
| 11 | `rank` | `rank.py` | 5.11 | Материальность, confidence, ранжирование, свёртка тривиального |
| 12 | `report` | `report/` | 5.12, 9 | Excel (основной), JSON (эталоны регрессии), HTML |

Вне конвейера: `signatures.py` (§8.1–8.2) — повторы, разрывы нумерации,
дубликаты, документы вне рабочих часов. Это то, что сверка не ловит по
построению.

## Команды CLI (§10 ТЗ)

```bash
cashforensics analyze <файл.xlsx> [--config CONF] [--target 0.00]
                                  [--out DIR] [--format excel,json,html]
cashforensics batch <директория> [--summary сводка.xlsx]
cashforensics verify <файл.xlsx>                     # только валидация §5.3
cashforensics explain <файл.xlsx> --finding <код>    # трассировка одной находки
```

Пакетный режим обязателен: сеть ПВЗ — десятки касс, нужна сводная таблица с
ранжированием по величине отклонения и числу находок (peer comparison).

Флаги обратимости (§12): `--no-collapse` и `--no-reversal-neutralization`
отключают любое автогашение и показывают сырую картину. `--audit-log` добавляет
лист журнала: что погашено, чем, каким правилом.

## Установка и разработка

Требуется Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync                      # окружение из uv.lock
uv run pytest                # все тесты
uv run pytest -m unit        # только юниты (§11.1)
uv run pytest -m synthetic   # синтетические кассы (§11.2)
uv run ruff check .          # линт
uv run ruff format .         # форматирование
uv run mypy                  # строгая типизация
```

Маркеры pytest соответствуют трём уровням §11: `unit`, `synthetic`,
`regression`.

Проверить разбор конкретной выгрузки:

```bash
uv run cashforensics verify путь/к/выгрузке.xlsx
```

Команда печатает найденную раскладку блоков, период, контрольные суммы и
результат каждого контроля V1–V6, а строки, которые не удалось отнести к
кассе, выводит списком с номерами — «тихих» пропусков нет (§12). Код возврата
1 означает нарушенный жёсткий инвариант: разбор неполон, и дальнейший анализ
дал бы правдоподобный, но неверный результат.

## Ключевые ограничения (§16 ТЗ)

Их обязан отражать каждый отчёт:

* Инструмент не может сказать, какая из двух систем права. Если суммы в
  проблемных ордерах подтвердятся подписями клиентов, ошибка окажется в выгрузке
  фронтальной системы, а не в 1С.
* Дисбаланс самих логов измеряется, но не объясняется: его причина лежит вне
  обоих файлов.
* Сигнатуры повторов **не являются уликой** — базовая частота повторов в этих
  данных высока.
* Датировка смещения даётся **окном**; точная дата из ряда сальдо не выводима.
* При отсутствии блока ПКО приход не верифицируется вовсе, и раскладка честно
  помечается «частично».
