# Регрессия на калибровочных кассах — §11.3 ТЗ

Маркер: `@pytest.mark.regression`. Снапшоты — `syrupy`, каталог
`__snapshots__/` рядом с тестом.

Девять реальных файлов с зафиксированными эталонами.

**Критерий:** совпадение сальдо, состава причинной раскладки (коды, суммы,
документы) и остатков свёртки. Расхождение — **блокирующий дефект**.

## Как запустить

```sh
uv run pytest tests/regression
```

Обезличенные выгрузки лежат в `tests/regression/fixtures/` и подхватываются
сами — набор идёт около двух минут. Переменная `CASHFORENSICS_FIXTURES` задаёт
другой каталог; если файла нет, тест **пропускается с явной причиной**, а не
падает и не подменяется синтетикой.

Снапшоты обновляются осознанно:

```sh
CASHFORENSICS_FIXTURES=... uv run pytest tests/regression --snapshot-update
```

Каждое изменение снимка обязано быть объяснено в коммите. Молчаливое
обновление снапшота превращает регрессию в тавтологию: тест начинает
подтверждать то, что код делает сейчас, вместо того, что он должен делать.

## Что попадает в снимок, а что нет

Только величины, коды §8, номера документов и счётчики. Свободный текст —
объяснения находок, титулы сигнатур — не попадает **никогда**: объяснение §8.1
цитирует получателя выдачи поимённо. Правило остаётся в силе и после
обезличивания фикстур: снимок не должен зависеть от того, псевдоним там или
настоящее имя. `meta.run_timestamp` исключён отдельно: он и есть отметка
прогона (§9.2).

## Дополнительные проверки, которые обязана делать регрессия

* **V1–V3 проходят на всех девяти** (§13.1).
* **`|unresolved| < EPS_TIE` на всех девяти** (§13.2).
* **Повторный прогон даёт побитово идентичный JSON** (§13.5) — тест запускает
  конвейер дважды и сравнивает байты, а не разобранный объект.
* **Остатки свёртки совпадают с таблицей §5.7.4** — критерий готовности
  этапа 1 (§14).

## Фикстуры

Обезличенные `.xlsx` лежат в `fixtures/` — как именно и чем доказано, что
обезличивание ничего не сломало, описано в `fixtures/README.md`. Оригиналы с
ФИО в репозиторий не кладутся ни при каких условиях.
